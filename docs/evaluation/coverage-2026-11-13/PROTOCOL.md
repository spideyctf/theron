# Coverage improvement regression protocol

This is a follow-up to Step 5, authorized to repair validation/test coverage. It is not a fresh held-out evaluation. All OWASP splits and prior outcomes were already exposed. Development source and selected exposed validation/test templates were inspected to understand unsupported APIs before this freeze. The independent real-code validation/test source remains closed.

Freeze the detector and original regression controls in Git before the next full validation/test runs. Compare against Step 5's unchanged file/CWE adapter, corpus revision, labels, helpers and split membership. Include every category and case; keep errors and label-matched false positives. Preserve Step 5 reports and baseline outcomes. Report each split separately, with per-category outcomes and case transitions. No claim of real-world accuracy follows from these tuning regressions.

The increment models weak hashlib choices, randomness flowing to cookie/session/token storage, request-to-session boundaries, explicit insecure cookie settings, SAX external-entity configuration, elementpath expressions, resolved LDAP filters and context-specific filter escaping. It also repairs caller-scope receiver resolution for imported methods, Base64/wrapper propagation and explicit shell argument vectors. XPath quote exclusions apply only within the matching quoted literal, with construction-time snapshots; they do not sanitize other grammars. Medium-confidence boundary/configuration findings require contextual review rather than asserting exploitation.

Original unsafe/safe controls cover aliases, shadowing, cryptographic generators, non-security randomness, parser isolation and disabling, bound XPath variables, quote-context mismatches, limited replacement, late variable overwrites, LDAP escaping, secure cookies and command argument position. Run the entire Python suite and existing frontend checks. Run all three OWASP splits and PySASTBench without executing corpus applications. PySASTBench's existing unresolved label remains an error, not a negative.

The user-requested recall target is at least 60% on the exposed validation and test splits, with false positives reported alongside it. Failing that target must remain visible. Achieving it is an engineering milestone, not evidence of industry-grade or publication readiness. Freeze identifiers, analyzer/adapter/rule hashes, raw outcomes and commands belong in the result packet.
