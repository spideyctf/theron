# Evidence integration and next research gates

14 November 2026. Initial implementation checkpoint `f370de1c7078e2b6e07154e2a8d4974ef757e3b1`. No manuscript is requested. Previous frozen results and the Requests project overlap remain intact; the inspected pilot is now development data.

1. **Detection mechanisms:** support HTML compatibility-normalization order, shared TLS pool policy, per-message MCP model-validation exceptions and raw AST-interpreter callable boundaries. Exercise original unsafe/safe/unresolved controls; retain explicit library and caller assumptions. Custom parent-object IAM requires additional source/policy evidence; do not invent authorization requirements from method names.
2. **Upstream execution:** use pinned target source and locked dependency wheels in the existing restricted namespace runner. Verify security failure on vulnerable code, security success after repair and legitimate-input tests on both. Begin with the in-memory MCP tests, then stage the remaining eight environments. CVAT's REST/database/service fixtures require a working isolated service environment; Docker's engine is currently unavailable. Record actual build/import/test failures and distinguish selected tests from full-suite acceptance. Do not execute target setup or install hooks on the host.
3. **Location/alert validation:** record exact file/function/action hashes and upstream test identifiers. Distinguish source-supported conditions, reproduced mechanisms, unrelated alerts and unresolved security use. These are author/assistant assessments corroborated by external tests, not independent human adjudication. CWE overlap and patch hunks alone are insufficient.
4. **OSV:** consume all query pages with a bounded page cap; fail incomplete lookups as coverage notices. Preserve advisory identities, package/ecosystem/version, manifest, fixed-version boundaries and upstream CWE labels through API/exports/frontend. Query actual repository manifests without installing packages. Separate declared version matches from runtime use. Public queries are used without a secret key; do not collect credentials.
5. **Correlation evaluation:** join supported MCP declarations, top-level import spelling and nearest exact OSV dependency declarations. Preserve uncertainty about distribution ownership and execution. Measure correctness on original positive/negative controls and run correlation-off ablation without changing vulnerability counts. This is an engineering check, not evidence of additional vulnerabilities or improved human review. Preregister a separately labelled real-repository and reviewer/automated-decision study before claiming that research benefit.
6. **Related work and final gate:** compare with established Python dataflow analysis and existing MCP scanners, including their supported tasks and assumptions. A general platform or a joined report is not novelty by itself. Keep fresh project-separated evaluation, independent location validation, real correlation benefit and production reliability as explicit acceptance gates. Passing tests or adding review context does not close those gates.

Acceptance for this increment: meaningful mechanism controls; real upstream paired tests where supported; live OSV receipts and failure handling; full Python/frontend regression and build; source hashes, explicit blockers and unchanged historical evidence. A new untouched reserve is required after tuning on these cases.
